# 标准工作流

## 1. 开始前

- 明确目标、非目标、验收标准和影响文件。
- 阅读相关实现、配置、文档、CI 和最近提交。
- 搜索现有组件、composable、工具函数和依赖，优先复用。
- 复杂任务创建变更计划；架构、依赖或行为兼容性取舍创建 ADR。

## 2. 修改中

- 遵循现有 Vue、命名、Prettier 和 ESLint 风格。
- 保持组件职责单一，避免把业务逻辑继续堆入页面模板。
- API、异步状态、空值、失败和移动端行为必须有明确处理。
- 不进行无关格式化、不修改锁文件之外的依赖元数据、不提交 secrets。

## 3. 完成前

- 检查 `git diff` 和 `git status`，确认没有误改或生成物。
- 代码变更至少运行 `pnpm lint` 与 `pnpm build`。
- 依赖变更确认 lockfile 一致；用户可见行为变更同步 README。
- 按交接模板写出验证结果、风险和后续事项。

## 风险分级

- 低：文案、纯样式、静态配置；至少检查 diff，必要时构建。
- 中：组件、状态、API、构建配置；必须 lint + build，并说明回归面。
- 高：依赖大版本、部署/CI、认证、数据格式、架构迁移；必须 ADR、验证方案和回滚方案，不能仅由 Agent 自行扩大范围。

## 完成定义

变更目标已实现；代码符合目录边界；相关文档和配置契约同步；验证命令有证据；已知缺口被明确记录；PR 描述可让下一位 Agent 无需重新猜测背景。
